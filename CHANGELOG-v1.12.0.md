# Bol-Khata v1.12.0 — Review build (partial)

## Step 0 changes
- `server/src/ledger.js`: shop avatar metadata now reads `o.hasPhoto` rather than checking the unselected `o.photo` buffer.
- `bol-khata-rn/app.json`: Expo app version is `1.12.0`; microphone, speech recognition, camera and photo-library permission descriptions now include Hindi and English.
- `bol-khata-rn/package.json`, `server/package.json` and their lockfile root package versions: bumped to `1.12.0` using `npm version` (lockfiles were not edited by hand).
- Photo endpoint decision: `GET /api/auth/photo/:userId` remains publicly readable for a user's uploaded profile image. It sends `Cache-Control: private, no-store`; the Avatar can keep using the public URL. This endpoint is not treated as private/authenticated by this build.

## Not completed in this review build
- Step 0.1 lockfile regeneration for `express-rate-limit@^8.1.0` could not be completed because npm registry DNS/network access failed (`EAI_AGAIN`). No manual lockfile edit was made. Do not consider a clean `npm ci` verified.
- The `hasPhotoFlag` regression test was added in `server/test/api.test.js`; full test execution is currently blocked because local dependencies are incomplete.
- Steps 1–3 (role/onboarding, business types and Item collection, itemized ledger entries, QR/UPI payment) are not implemented in this build. This is a partial review ZIP, not the requested feature-complete release.

## Validation status

## Additional implementation work (2026-10-12)
- Added `User.role`, `roleChosenAt`, and `businessType` fields. New email and mobile signups now require a `seller` or `buyer` choice; legacy users who already own ledger customers are migrated to seller when their authenticated session is used.
- Added authenticated role/business-type endpoints and server-side seller-only guards for shop ledger/report/backup endpoints.
- Added owner-scoped item catalog endpoints (`GET/POST /api/items`, `PATCH /api/items/:id`) with unit/name/price validation and a 200-item cap.
- Added `photoFlags.hasPhotoFlag()` and a regression test ensuring avatar metadata relies on `hasPhoto`, not the unselected `photo` binary.
- Signup UI now sends the selected seller/buyer role for email and OTP flows.

## Verification caveats
- npm registry access timed out during lockfile regeneration; do not treat `npm ci` as verified. The lockfile still needs to be regenerated by `npm install express-rate-limit@^8.1.0` in a network-enabled environment.
- These changes are not a claim that all requested onboarding, itemized transactions, QR/UPI buyer flows, translation/theme cleanup, or production checks are complete. See MIGRATION-v1.12.0.md and the delivery notes for remaining work.
